# 验收与迭代

## 先记录证据

多镜头清单先按 [分镜检查](shot-manifest.md) 核对结构、时间和本地文件；异步结果按 [分层验收](generation-jobs.md) 区分下载、技术检查与视听接受。脚本不会判断媒体可解码或画面真实，完成技术检查后再做以下内容验收。

记录文件、版本、时码、检查方式、实际看到/听到的事实、预期与偏差。抽帧只说明所检查的画面，完整运动和声音需单独检查。无法听音时不能判台词清晰、音色正确、声画同步。

按次序检查：
1. 叙事：普通观众能否说清谁做了什么、为什么、结果是什么？
2. 因果：关键动作、接触和结果是否真的出现？
3. 身份：脸、服装、体型、真人/Q版归属是否一致？
4. 连续性：位置、视线、手中物、屏幕、道具数量、开合状态是否合理？
5. 表演声音：说话归属、字句、目的和回应是否可辨？情绪是否有触发？
6. 节奏：有无重复信息、无用等待、来不及理解的切换？

按素材类型再检查：口播核对否定词、条件、数值单位、观点归属和总结成员；动态图文核对真实字体、稳定阅读时间与中间运动；人物合成核对同步、边缘、内部裁切和声音重复。相应细节见 [口播](narration-motion.md) 和 [动态图文](motion-layout.md)，不把这些额外项目套给无关镜头。

程序制作交付按 [执行模块](execution-adapters.md) 检查媒体可解码、时间范围、首末帧和工程入口。脚本、播放器、媒体和说明应指向同一交付版本。完整成片按实际观看与试听范围判断；只有抽帧或响度数值时记录其覆盖范围，不将其升级为整片视听通过。

纯声音修改且画面无需变化时，优先复用合格画面；改一个标题则检查对应阅读段与邻接转场。已经通过且未受影响的部分不因新增规则自动重做。

## 判定与处理

| 判定 | 条件 | 操作 |
|---|---|---|
| 保留 | 核心叙事和连续性成立 | 记录可用时段和真实末态 |
| 后期修复 | 裁剪、字幕、音量等能修且不伪造关键动作 | 写具体时码与操作 |
| 局部补拍/编辑 | 独立缺口可被替换且平台支持 | 保留合格部分，明确接点 |
| 重新生成 | 任务合理但本次执行失败 | 说明改变的变量与验收点 |
| 改写镜头 | 多重动作/参考冲突或本身讲不清 | 简化事件或换表现方式 |
| 停止当前方法 | 同类错误反复或接近授权成本上限 | 汇报证据，给替代方案，停止盲抽 |

同类失败连续两次后，默认先重审参考图与动作设计；这不是模型失败概率结论，也不越过用户给定的重试预算。诊断用“观察到／推测／尚未排除”区分事实和归因。

保留的片段记入 accepted-takes.md：任务ID、文件、可用入出点、真实末态、声音末态、尚存问题。弃用素材不进入接续参考。

## Skill 更新规则

外部教程或新Skill的采纳先按 [证据清洗](evidence.md) 分离实见、宣称与推断。资产修正后按上游依赖标记下游待复核，不默认重做整片。

用户提出迭代时记录：失败证据 → 原规则为何不足 → 最小改动 → 适用范围 → 检验结果。项目偏好写项目约定，通用决策写核心或对应参考。不要因一个镜头失败新增“永远禁止多人/永远禁止Q版”等禁令。

验证分三层：文件结构与链接；模拟任务的行为检查；真实模型样片。前两层通过不能声称生成效果已验证。
