# 制作执行与工具边界

用于用户要求实际图片、视频或可编辑工程时；只写方案、解释术语或局部文案不用先装整套环境。图片制作调用流程见 [关键帧生图执行](keyframe-generation.md)，制作依赖和资源安排见 [制片统筹](production-coordination.md)。

## 选择本次执行路径

| 当前表达任务 | 优先考虑 | 必须确认的实际条件 |
|---|---|---|
| 保留真人原话并包装 | 原片剪辑与合成 | 媒体可读、时间轴、字幕精度、声音 |
| 精确文字、流程、数据、UI或可控空间动效 | 程序动画或现有后期工程 | 可用引擎、字体资产、取帧/渲染及编码入口 |
| 表演、情绪或现有素材缺失的影像 | 实拍或生成式视频 | 拍摄条件或真实可调用服务、参考与授权 |
| 多种素材组合 | 按镜头分配以上路径 | 画幅、帧率、色彩、声音和接点能匹配 |

可以组合，但不要因安装过某个库就把所有镜头改造成它擅长的风格。已提供剪映、AE或其他可用工程时优先沿用，不为引入工具重建已合格内容。

## 明确谁在工作

执行者是当前有文件、命令或平台工具权限的智能体。Skill 提供决策与操作指导；Three.js 等引擎绘制画面；FFmpeg 等工具处理媒体。Skill 名称不是独立运行的模型，写完提示词也不等于已经调用生成服务。

按当前任务核实所需能力：文件与素材能否读取、所选引擎能否运行、是否能导出、实际画面和声音能用什么方式检查。已有可靠验证只在相关能力变化或失败时重查。缺工具时完成可做部分并明确具体缺口；不要报称生成完成。

## 程序动效的最小工程要求

沿用当前工程的资源与时间系统。没有现成工程时，在本片目录保存场景、资源、时间配置、预览/导出入口和媒体输出。文案和时间最好与绘制逻辑分离，以便局部修改，但不为短任务强建复杂框架。

预览与导出使用一致的场景状态；在指定时间取得画面前等待字体、纹理及视频帧就绪。需要随机效果时固定种子或缓存；复杂模拟按引擎能力烘焙。重复查看同一时刻应稳定，不依赖机器播放速度或上一次播放历史。

先验证所选路径能输出一小段，再扩大高成本任务；若已有本片合格渲染路径则复用。最终核对文件可解码、实际尺寸和时长、帧率依据、首末内容与音轨。程序检查和视觉听觉判断分开。

可编辑工程的类型要说清：网页/Three.js源码、AE工程、剪映工程等不能互相冒称。媒体、资源、配置、预览和复现命令指向同一版本；分享交付包含必要资源与许可，不把本机绝对路径当远端可访问素材。

## 外部工作区接入

要调用已安装的 Agent Motion 等工程时，先确认真实目录与版本，再读它的入口、工具说明和许可；使用该工程的本地 Skill，不假定同名全局文件等价。自身制作规则有冲突时按用户有效要求和项目范围解决，技术与许可条件不能凭默认偏好忽略。

外部工程的代码、Skill、字体、模型与案例按各自许可使用。Agent Motion 的非商业限制见 [来源说明](sources.md)；柚导不将它设为默认或必需引擎。没有适用授权或不合项目需求时，保留方案并另选适用工具。

所需软件、浏览器、路径与版本保存在当前项目配置或记录，不写成本技能所有机器通用的固定值。本机安装报告属于历史验证，下一次使用只复核涉及的组件，不凭过去 smoke 测试保证新片边缘、声音或审美。
