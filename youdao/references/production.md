# 生成与交付

## 资产台账

用户要求生成关键帧、分镜图或资产图时，先按 [关键帧生图执行](keyframe-generation.md) 调用工具并验图，再将实际文件纳入台账。这里只规定生成式视频的任务组织，不能把填完任务卡当成图片已制作。

资产筛选、上游依赖及版本变化按 [制作基准与资产依赖](asset-baseline.md) 执行。表中新增信息可维护在同一台账，不另建互相冲突的清单。

| ID | 文件绝对路径/链接 | 缩略图 | 控制内容 | 不继承内容 | 状态 | 用于哪些任务 |
|---|---|---|---|---|---|---|

状态用已确认、待修、待制作、弃用。真实脸照控制身份，服装图控制服装，场景图控制布局；风格图不能偷换人物长相。一个角色的同一维度只有一个明确的优先来源。上传序号是执行映射，不自动决定权威。图上人物有错时先修图，不写“严格保持一致”延续错误。

台账覆盖声音参考和角色状态。检查实际文件可读性；引用位置给绝对路径。项目已有声音参考但当前无法访问时记用户已提供，不假装已试听。

## 模式选择

有空间调度或运镜时按 [空间、镜头与灯光](camera-light-space.md) 写起点、路径与落点；复杂动作按 [动作连续性](action-continuity.md) 明确接触、反馈和末态。只展开本镜需要的内容。

| 需求 | 候选方式 | 注意 |
|---|---|---|
| 明确起始构图、简单动作 | 单张首帧 | 起始图内的人物、手、屏幕须先合格 |
| 必须从A到B且过渡可实现 | 首尾帧 | 两端保持身份、空间、尺度；验证当前平台支持 |
| 多人/场景/产品要分别控制 | 多参考 | 明确每张用途，参考上限以当前界面或官方资料为准 |
| 一段含多个关键状态 | 故事板参考 | 格号对应时间和信息，不能承诺逐格精确复刻 |
| 复杂互动失败或风格切换不稳 | 分开生成 | 用户要求整段直生时先交付该方式，替代方案另列 |

九宫格按阅读顺序编号，格子描述关键状态而非九个几乎相同的角度。单格用于首尾帧时另导出无边框清晰图，检查分辨率。九宫格的脸不能覆盖确认身份照。

平台信息单列“平台／具体模型／网页或API／模式／时长／画幅／参考限制／声音支持／核验日期及来源”。用户界面证据与官方文档优先。Seedance 2.0的参数不能套给2.5；不确定时提供期望时长及待核验字段，继续写可执行内容，不编参数。

参考数量受限时优先保留不可由文字替代的身份、关键结构、空间及本镜状态；按画面重要性选择，不为每个道具都上传一张图。装饰性风格参考可转成文字，无法兼容的参考不强塞。限制不足以维持关键事实时拆镜或补首帧，说明依据。

## 真人与Q版

Q版是可说话、可行动的叙事形式。先确定项目中的规则：全画面切换、局部主观表现还是独立反应镜头；无意出现真人旁边的迷你分身属于错误。服装、发型、眼镜等辨识元素与对应真人匹配。

按用户选择走两条路线之一：
- **整段直生：** 提示词明确真人的触发动作 → 切至Q版的表演和短句 → 切回真人的终态。不能写“由剪辑师插入”。先用一个代表片段试验，失败再建议分开生成。
- **独立素材：** 为Q版制作单张关键帧及独立提示词，把后期插入位置放在人类执行栏。生成最短时长仍超过需要时，优先设计可用两三秒的动作/短对白小场，或同场景同认知状态的连续反应素材；不机械生成四秒只用零点几秒。

Q版时长与频率服务事件，不平均撒表情包。重大情绪可由真人或Q版承担，服从项目风格；具体影片的结尾人物形式只从该片项目约定读取。批量生成不等于把互相矛盾的情绪和不同场景塞进同一条。

## 单段任务卡（图与词必须同处）

1. 任务ID、版本、当前状态、本段让观众理解的事。
2. 成片起止时间；请求生成秒数；预计使用秒数；实际可用秒数待验收填写。
3. 参考图缩略图、绝对路径、上传顺序及用途；缺图明确阻止把该卡标为可执行。
4. 生成模式和界面需选择的设置。
5. 节拍表：本次视频相对秒点、景别/机位、动作、台词说话者、听者反应、声音、终态。秒点是导演目标，不是平台执行保证。
6. **可复制视频提示词**：只写本次模型生成内容。
7. **人工操作**：上传、选择模型、下载命名、后期拼接/字幕/音轨等；与提示词分开。
8. 本段验收三至五项、接续对象、失败时最小修复方式。

## 提示词编写顺序

修订时从当前有效事实重新编译；弃用参考、旧台词和历史纠错过程留在记录里，不堆进本次模型指令。

当前参考绑定与职责 → 开场状态 → 按时间推进的镜头和动作 → 台词及可执行表演 → 声音 → 完成状态 → 少量关键约束。

使用平台真正支持的引用语法；未知时写“上传参考图1”等可理解名称并标注需按界面绑定，不能把文件路径当作模型已收到附件。计划表可用ID，最终提示词不塞台账、导演心理分析、整片未来剧情或验收指令。

一个生成单元承载一个清楚的事件，不必只有一个镜头。参考已经表达的细节不反复堆写；优先说明变化、互动先后、身份高风险点。写“镜头切到听者，他收回伸出的手”比“紧凑、震撼、情绪拉满”更有执行意义。

正式直生任务须写齐台词及说话者，不擅自将用户要生成的对白改为后配。多角色抢话/旁白压对白难以辨认时先重排台词，确需独立配音则说明替代流程。估时应包含停顿与动作；超时先减内容或拆任务。

连续动作片段：后续提示词草稿可以提前交付，但标为待前段验收校准。只有实际接受的前段末帧/末态才能用于最终接续。不依赖前段动作的家庭插镜等可独立批量生成。

## 图文文档

批量交接的镜头表可按 [结构化清单](shot-manifest.md) 检查编号、主时间线、素材和状态；实际异步提交与结果回收按 [生成任务](generation-jobs.md) 记录。检查器通过不等于可交付，下载也不等于视听通过。

本页的任务卡与模型参数适用于生成式制作。原片包装或程序合成使用 [口播](narration-motion.md) 与 [执行](execution-adapters.md) 模块中的同一份项目记录，不为它们强造生成提示词、上传参考或生成秒数。

每张任务卡在同一章节展示图、路径、秒数和复制区；制作人能直接找到上传文件。HTML图片使用相对资源链接时验证解析到真实文件，交付入口用绝对路径。检查图片加载、文字可读、复制区不混入人工指令、时长加总及版本一致。打包分享时把被引用资源一并打包，不把本机路径冒充可分享资源。
