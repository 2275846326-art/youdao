# 异步生成任务与结果验收

仅在实际提交生成或回收异步结果时使用。沿用当前项目台账，不绑定某一供应商、账户或本机目录。

提交前保存本地任务 ID、镜头版本、输入文件及摘要、完整参数、授权范围、提交意图和时间。提交返回后立即保存平台 job ID、返回状态与结果入口。支持幂等键的平台使用稳定请求键；不支持时，先查平台历史确认是否已提交。

状态分开记录：draft → submitting → submitted/running → downloaded → technical_checked → reviewed；失败可记 failed，提交超时且无法确认的记 unknown。网络超时不是生成失败；unknown 先查询，无法核实时报告状态并保留材料，不自动重复计费提交。重新生成使用新版本，并关联原任务。

结果归属优先按平台 job ID 与返回结果映射，辅以输入摘要、时间和规格；不能仅按目录中“最新 MP4”认领。同一文件默认不能被多个任务各自宣称是独立生成结果；复用时明确指向原结果。并发更新台账使用单写入者或经过测试的锁及原子替换；没有实现并发安全时串行回收。

验收分层：
1. 下载：真实文件完整落盘，非零大小，来源可追踪。
2. 技术：用可用媒体工具确认视频流、可解码、时长、尺寸及所需音轨，检查不符的规格。没有工具就标未检查，不猜通过。
3. 内容：正常速度看动作、空间、身份、语义和接续；需要声音时实际试听。
4. 接受：记录通过范围、剩余问题及用户明确确认（如有）。

扩展名、容器标签、浏览器提示“完成”、任务日志或文件大小稳定只能提供局部证据，不能替代后续层级。计划、已下载、技术通过和可交付不得混称。本模块是执行规范，不包含后台轮询服务或平台接口；沿用工具支持的等待机制，不承诺离线自动续跑。
